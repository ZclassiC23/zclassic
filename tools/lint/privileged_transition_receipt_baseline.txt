# check_privileged_transition_receipt.sh baseline — Law-7 dispositions.
#
# Every native command leaf whose spec is ZCL_COMMAND_AUTH_OWNER AND effect
# ZCL_COMMAND_EFFECT_MUTATE or ZCL_COMMAND_EFFECT_DESTRUCTIVE is a candidate
# privileged transition. Each such leaf MUST have a disposition here; a new
# owner-mutating leaf with none FAILS the gate, forcing a conscious Law-7
# review. RATCHET: this file only grows when a genuinely new owner-mutating
# leaf is added — and it should grow with `receipt:` far more often than
# `exempt:` from now on.
#
# Line format (one leaf per line; `#` comments / blank lines ignored):
#   <leaf.path>  receipt:<relative_file>   # binds an authority_receipt verifier
#   <leaf.path>  exempt:<one-line reason>  # not an artifact-install transition
#
# For a `receipt:<file>` line the gate additionally asserts <file> contains a
# call matching authority_receipt_.*_available( OR the pre-generalized
# consensus_state_replay_receipt_authority_available( — a positive check that
# the wired consumer actually gates on the contract.
#
# Today's universe (25 leaves — the initial baseline, all `exempt`). The first
# real privileged artifact-install transition surfaced as an OWNER leaf (bundle
# ACTIVATE, hot-swap Phase-3 reopen, `make deploy` generation publish, App
# cartridge activation) lands here as `receipt:<handler_file>`.

# Vault custody verbs (config/commands/vault.def). None of them builds, signs
# or installs anything: each resolves the path that already owns the spend and
# dispatches to it, so the Law-7 disposition of the routed leaf governs. If a
# vault verb ever grows its own artifact install it stops being a route, and
# this line must become a receipt:.

# Agent session grants (config/commands/vault.def). Minting/revoking writes an
# agent_sessions ROW through the AR lifecycle — a scoped, revocable grant
# record in node.db, not a privileged artifact installed over the datadir or
# the running binary, and the row is itself fail-closed policy input (an
# over-broad grant still passes through the ceiling/caps the kernel derives
# from the principal's role).
vault.session.create       exempt: AR insert of an agent_sessions grant row; no artifact install
vault.session.revoke       exempt: AR update marking an agent_sessions row revoked; no artifact install

# Wallet key-disclosure and wallet-recovery leaves (config/commands/core.def).

#
# export-key was reclassified from EFFECT_READ/RISK_READ to
# EFFECT_MUTATE/RISK_WALLET (it writes a raw spending key to the caller's

# app.store.* — the buying half of the store. None of the three installs a
# privileged artifact over the datadir or the running binary.
#   order   writes an app-layer purchase row (store_purchases) plus the
#           merchant's own order row, both ordinary AR records in node.db.
#   pay     moves value, but the spend is already covered by the node's
#           sovereignty spend guard (sovereignty_guard_allow("wallet_spend"))
#           and by z_sendmany's own path; this leaf adds no new authority.
#   collect writes a buyer-chosen data file whose bytes are SHA3-256-bound to
#           the product content hash BEFORE the write, and the write is
#           atomic-by-rename — a mismatch leaves nothing behind at all.
app.store.order            exempt: AR insert/update of a buyer purchase row; no artifact install
app.store.pay              exempt: shielded spend already gated by the sovereignty spend guard; no artifact install
app.store.collect          exempt: writes a content-hash-verified data file to an operator-chosen path; no artifact install
app.tokens.create          exempt: broadcasts a wallet transaction through the existing sovereignty, admission, durability and relay gates; installs no privileged artifact
app.tokens.mint            exempt: broadcasts a mint-baton-authorized wallet transaction through existing spend gates; installs no privileged artifact
app.tokens.send            exempt: broadcasts an explicitly token-funded wallet transaction through existing spend gates; installs no privileged artifact
vault.send-token           exempt: dispatch-only alias of app.tokens.send; builds or installs nothing itself
core.wallet.transaction.raw.create    exempt: composes unsigned transaction bytes only; mutates no node or wallet state and installs no artifact
core.wallet.transaction.raw.sign      exempt: produces signatures with resident wallet keys but imports nothing, persists nothing and installs no artifact
core.wallet.transaction.raw.broadcast exempt: submits bytes through the shared mempool acceptance and relay gates; installs no privileged artifact
core.wallet.recovery.restore    exempt: derives a wallet's own keys from an operator-supplied phrase and writes them into an EMPTY datadir through the node's own schema path; refuses while a node holds the datadir and refuses outright if a wallet is already there; installs no artifact and changes no running binary
