# Telemetry-ontology scan manifest — the declared coverage surface of
# tools/lint/check_telemetry_ontology.sh.
#
# One row per (subsystem, owning .c file, emitting function, JSON target
# variable) tuple. The gate slices each named function out of its file,
# extracts every scalar field emission inside it
# (json_push_kv_int / _str / _bool / _dbl / _uint), maps the emission's target
# object variable to the JSON path prefix named here, and requires the
# resulting `<subsystem>|<prefix><field>` key to carry a meaning row in
# lib/util/include/util/telemetry_ontology.def.
#
# Two ways this bites:
#   * a NEW field emitted inside a covered function with no ontology row
#     -> UNANNOTATED FIELD (named, with file:line)
#   * a NEW json target variable inside a covered function that this manifest
#     does not map -> UNMAPPED EMISSION TARGET (the manifest must be extended
#     before the field can ship)
#
# Columns: <subsystem> <file> <function> <objvar> <prefix>
#   objvar  the literal first argument of the emission call ("out", "&pf", ...)
#   prefix  the JSON path prefix that object sits at, or "-" for the dump root
#           ("[]" in a prefix marks an array of objects)
#
# Covered subsystems are the six that answer the live peer/sync questions:
# peer_lifecycle, connman, addrman, network, fast_sync, sync_rate.

# ── peer_lifecycle (lib/net/src/peer_lifecycle.c) ────────────────────────
